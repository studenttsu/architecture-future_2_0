# Задание 3 — технический радар «Будущее 2.0»

Техрадар реализован в tech_radar директории на основе учебника Практикума.

**Сценарии:** **S1** финтех-продукт · **S2** ИИ и PHI · **S3** партнёры · **S4** отчётность и миграция с DWH · **S5** self-service без PHI.

| Технология / практика | Квадрант | Кольцо | Поддерживаемые сценарии | Комментарий |
|------------------------|----------|--------|-------------------------|-------------|
| Python (ИИ-сервисы) | Языки и фреймворки | Активно используем (adopt) | S2 | Стек ИИ; обмен только по контрактам наружу из PHI-контура. |
| Go / Java (финтех) | Языки и фреймворки | Активно используем (adopt) | S1, S4 | Доменные сервисы; события продуктов не через новые пакеты в DWH. |
| T-SQL / хранимый контур DWH | Языки и фреймворки | Выкидываем как центр изменений (hold) | S4 (наследие) | SQL Server 2008: исторический источник и CDC, **без** новой доменной логики в ядре. |
| Data Mesh / domain data products | Практики и паттерны | Пробуем (trial) | S1, S3, S4 | Автономия доменов и контракты данных вместо «всё в DWH». |
| CDC / event-driven ingestion | Практики и паттерны | Пробуем (trial) | S1, S4, S5 | Потоки в lakehouse и интеграцию без расширения трансформаций в DWH. |
| FinOps / SLO по доменам | Практики и паттерны | Изучаем (assess) | S1, S2, S5 | Прозрачные затраты и качество сервисов при росте данных. |
| OpenTelemetry / наблюдаемость | Практики и паттерны | Изучаем (assess) | S1–S5 | Трассировка и SLO для финтеха, интеграции и аналитики. |
| SQL Server 2008 (DWH) | Платформы | Выкидываем как центр изменений (hold) | S4 | Легаси-платформа; снимаем с неё продуктовые изменения и отчётный «центр тяжести». |

| Kafka / managed events | Платформы | Пробуем (trial) | S1, S2, S3, S4 | Шина событий вместо точечных доработок только в DWH. |
| IAM / RBAC / OAuth2 | Платформы | Пробуем (trial) | S2, S5 | Разграничение PHI и корпоративной аналитики; аудит доступа. |
| Apache Camel (ESB) | Платформы | Пробуем (trial) | S1–S4 | Эволюция к API + события; не хранилище истины. |

| Портал самообслуживания | Инструменты | Пробуем (trial) | S5 | Каталог, конструктор, RBAC; требование бизнеса из landscape. |
| Каталог данных | Инструменты | Пробуем (trial) | S3, S5 | Обнаруживаемость наборов и контрактов для доменов и аналитиков. |
| Apache Airflow (или облачный оркестратор) | Инструменты | Пробуем (trial) | S4, S5 | Пайплайны CDC и курирования без «ручных» цепочек в DWH. |
| PowerBuilder (клинический UI) | Инструменты | Выкидываем как центр развития (hold) | S2 (операции) | Операционный контур; узкое место по развитию — план отказа в пользу целевых каналов там, где возможно. |

## Легенда колец (кратко)

- **Adopt** — уже в промышленном использовании или принимается как стандарт домена.  
- **Trial** — пилоты и целевой горизонт ~1 год по [роадмапу](roadmap.md).  
- **Assess** — оценка перед масштабированием.  
- **Hold** — легаси или направление, от которого **снимаем** продуктовую и отчётную нагрузку (не «удалить завтра», а изменить роль в ландшафте).

# Роадмап изменений технологического ландшафта «Будущее 2.0»

## Связь с целями бизнеса

| Горизонт | Цель бизнеса (landscape) | Технологический фокус |
|----------|--------------------------|------------------------|
| **~2 месяца** | Согласованная архитектура трансформации; границы доменов; проекты витрины | Зафиксировать целевой стек (lakehouse, интеграция, IAM); пилот CDC; политики PHI |
| **~1 год** | Портал самообслуживания; пользователи доменов на новой архитектуре; легаси допустимо изолированно | Портал + семантика + lakehouse consumption; события из финтеха/партнёров; качество мед/фин сервисов |

## Этапы, результаты, команды, ресурсы

### Этап A — 0–2 месяца (фундамент и согласование)

| Поле | Содержание |
|------|------------|
| **Бизнес-цель** | Закрыть промежуточные цели landscape: архитектура согласована, домены и связи описаны, запланированы проекты витрины. |
| **Ожидаемые результаты** | Утверждённая целевая C4; RACI по доменам; **политики разделения PHI и корпоративной аналитики**; дорожная карта CDC из DWH; MVP каталога данных; выбор облачного региона и baseline IAM. |
| **Ответственные** | CDO / офис данных; **платформенная команда** (интеграция); **DWH**; **ИБ и комплаенс**; архитектурный комитет. |
| **Ресурсы** | Бюджет пилота (облачная песочница); 1–2 SRE/платформенных инженера; внешние консультации по регуляторике (мед/фин); время владельцев доменов на согласование контрактов **S1–S5**. |

**Вехи (технологии):** референс-развёртывание lakehouse (trial), дизайн топиков Kafka/Event Hub, **аудит доступа** к DWH и будущей витрине.

---

### Этап B — 2–6 месяцев (lakehouse, события, портал MVP)

| Поле | Содержание |
|------|------------|
| **Бизнес-цель** | Ускорить отчётность и снизить зависимость от DWH как места новой логики; начать **S5** без PHI; поддержать **S1** через события. |
| **Ожидаемые результаты** | Поток **S4**: CDC/батчи в lakehouse (raw/curated); контрактные события **S1** из финтеха в интеграцию; **портал MVP** (каталог ограниченного набора датасетов, RBAC); семантика для ключевых KPI; Power BI на семантике / витрине. |
| **Ответственные** | Домен **финтех**; **интеграция**; **корпоративная аналитика**; **DWH** (выгрузки); **ИИ** (контуры S2 без смешения с витриной). |
| **Ресурсы** | Кластер lakehouse (облако); лицензии BI; FTE аналитиков данных на моделирование curated; обучение бизнес-пользователей порталу. |

**Вехи:** оркестрация (Airflow или облачный аналог) на прод-пилот; **SLO** на цепочки загрузки; мониторинг финтех-API (**качество фин. сервисов**).

---

### Этап C — 6–12 месяцев (полноценный self-service, партнёры, качество мед/фин)

| Поле | Содержание |
|------|------------|
| **Бизнес-цель** | Финальное состояние landscape: портал самообслуживания; домены работают в новой архитектуре; **качество медицинских и финансовых сервисов** на уровне продакшена. |
| **Ожидаемые результаты** | **S5:** конструктор отчётов и политики «без медкарт в consumption»; **S3:** партнёрский шлюз и курированные потоки; **S2:** регламент ревью моделей, журналы качества, изоляция PHI; **DR и георезерв** для критичных контуров; единая наблюдаемость (OpenTelemetry trial→adopt по доменам). |
| **Ответственные** | Все **доменные владельцы**; **SecOps**; **клинический контур**; **финтех**; **партнёрский офис**. |
| **Ресурсы** | Продовое облако (масштаб под сотни ТБ); FTE сопровождения; бюджет на независимые релизы доменов; процедуры инцидентов и аудита для финтеха и клиники. |

**Вехи:** нагрузочное тестирование отчётности; **пен-тест** API и портала; playbook инцидентов для **мед** и **фин** данных.

---

## Трассировка сценариев по этапам

| Сценарий | Этап A | Этап B | Этап C |
|----------|--------|--------|--------|
| **S1** Финтех-продукт | Контракты событий, шина | Прод-события, версионирование | Независимые релизы без DWH |
| **S2** ИИ и PHI | Политики и границы контуров | Интеграция результатов по API | Ревью моделей, аудит |
| **S3** Партнёры | Шлюз в дизайне | Пилот B2B | Прод + мониторинг |
| **S4** Отчётность / DWH | План CDC | Lakehouse curated | Смещение нагрузки отчётов |
| **S5** Self-service | Требования RBAC | Портал MVP | Полный конструктор |
